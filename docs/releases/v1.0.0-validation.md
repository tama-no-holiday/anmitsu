# anmitsu 1.0.0 ソースの検証結果

対象: 書き出したソース（元のコミット `0283d4e`、versionName 1.0.0・versionCode 1、パッケージ名 `io.github.tama_no_holiday.anmitsu`）。どれも開発者の環境で実行したもので、ツールは既存のものを使っています。

**まとめ:** A・B は当時の記録です。辞書・AIを入れた検証（A）では debug・release の `:app` テストがそれぞれ1件失敗しました。その原因はテストの待ち方と期待値で、テストを直したあと、辞書・AIを入れた構成で core・oss・debug・release のテストを実行し直し、失敗・エラーは0件でした（E）。lint はエラー 0・警告 3 で、署名していない確認用のAPKを作りました。置き換える署名済みの配布用APKはまだありません。

## A. 辞書・AIを入れた検証（当時の記録）

既存のツール・キャッシュと、既存の辞書・AIのファイルを使って、最初の書き出しの複製で実行しました。

### A.1 テスト

| 対象 | 結果 |
|---|---|

| `:core:test` | 118件合格 |

失敗したテスト（どちらも `InputUiTest`、debug と release で別のテスト）:

- debug: `backspaceHonoursACaretTappedInsideTheSelectedSegment`（1103行）。期待 `[あしは|, 雨]`、実際 `[明日|, 雨]`。このテストだけを実行し直すと合格しました（1件中1件）。
- release: `backspaceOnTheFirstSegmentDeletesItsLastKanaThenContinuesBackwards`（1013行）。期待 `[あし|, 、, 雨]`、実際 `[朝|, 、, 雨]`。実行し直していません。

当時は原因を確かめていませんでした（その後の診断と修正は E）。当時、テストのコードを読んで分かったのは次の2点だけです。

- 待ち合わせの補助関数 `pumpUntil` は、条件がそろわないまま 300回×10ms が過ぎても失敗せずに戻ります。
- 1013行のテストのコメントには「あし: no word」とありますが、別のテストは、試験用の辞書が「あし」を「朝」に直すことを前提にしています。

どちらも、テストの期待値か待ち方の問題を疑わせますが、根拠にはなりません。利用者に見える不具合かどうかも確かめていません。アプリとテストは変えていません。

## E. A の2件の失敗の診断とテストの修正（2026-11-23）

上の A・B の結果は当時の記録として残します。

### E.1 診断と修正

- core の診断では、2件のテストケースがどちらも合格しました（Gradle の報告で40秒）。コストの低い候補が先頭になります。`あし` の変換は 朝（読み `あさ`、3.7）が先頭で、そのままの `あし` は 4.0。`あしは` は 明日（読み `あした`、4.1）が先頭で、そのままの `あしは` は 5.0。どちらも、そのままの読みの候補は残っています。
- 失敗のしくみ: 2件のテストは、途中のかなや読み込み中の仮の表示を受け入れていました。今のライブ変換は、補正した候補の先頭を表示に使います。そのため、待ち合わせの時点によって `あし` / `あしは` と `朝` / `明日` のどちらにもなりました。
- 直したこと: 2件の UIテストは、意図した入力の読みと、仮の表示ではない変換候補がそろうまで、上限つきで待ち、時間切れなら失敗します。そのうえで、そのままの読みの候補（チップ）と表示を確かめます。削除・カーソル位置・エディタについての確認はそのまま残しています。テストの待ち方と期待する表示だけを直し、アプリの実行時の動作は変えていません。
